# Native VR Settings entry and glyph patches for Death of the Outsider (research)

Read-only research, 2026-11-22. Nothing in `src/`, `launcher/`, `build/` or the game was touched, and the game process was
not attached to. All numbers come from the on-disk resource archives of both installs (extracted into a scratch directory),
`tools/iggy_abc.py`, and a proof-of-concept generator (appendix) that reproduces D2's shipped patched movies byte for byte and,
run on DOTO's movies, produces patched DOTO movies whose disassembly is what we want.

## 1. How the D2 mod does it

**Mechanism: in-memory, same-size AS3 (ActionScript 3 bytecode) edits applied after the game has loaded the movie.
No movie file is ever written to disk; there is no replacement movie and no injected ActionScript source.**

| Piece | File | What it does |
|---|---|---|
| Load hook | `src/native_menu_entry.hpp` (`load_hook`, RVA 0x2E4D0 in D2) | Calls the original `arkIggyFilesManager` file read, then reads the manager: the whole decompressed movie is at `*(m+0xA708)`, size `*(m+0xA710)`, path string at `m+0xA608`. It matches the path suffix and patches the buffer in place before Iggy creates the player from it. Idempotent (an already patched cached buffer is accepted). |
| Edit table (VR Settings) | `src/menu_patches.hpp`, generated by `tools/gen_menu_patches.py` | Per movie: `suffix`, exact `size`, a list of `{file offset, old bytes, new bytes}` (same length), `original_sha256`, `patched_sha256`. Movies: `corvo_pause_menu.iggy` (518171 B), `emily_pause_menu.iggy` (517579 B), `main_menu.iggy` (542805 B). |
| Pinning | same | Refuses unless `size == movie.size`, every edit's old bytes are present (or all new bytes, i.e. already ours) AND the SHA-256 of the whole buffer equals `original_sha256`. Any mismatch leaves the movie untouched and bumps `mismatched` (this is the "refused" in docs/DOTO-VR.md section 2). |
| Hub hook | same file (`hub_hook`, RVA 0x34800 in D2; DOTO 0x35630 reads a 4th register, already forwarded) | The Iggy external-call hub. The patched AS3 sends `GameService.sendNotification("VR_SETTINGS_EVT")` (pause) or `"VR_SETTINGS_OPEN_REQUEST"` (main). The hub answers it (returns 1) and queues the real work on the engine's deferred external-call queue (`on_deferred`), which opens the native VR options page. It also answers `VR_SETTING_CHANGED`, `VR_SETTING_ACTION_n`, and `OnBackFromSettingsList` / `OnRestoreSettings` for instance 100. |
| Native page | `src/native_options_page.hpp`, `docs/native-vr-options-page.md` | Writes `optionsData.currentSection` (label, instanceIndex 100, rows with slider/stepper/toggle) through the Iggy API and calls `root._C_ShowOptionSection()`, so the game's own `lib_options` list, fonts and widgets draw the page. |
| Glyph patches | `src/controller_glyph_atlas.hpp` (`native_art_movie_edits[]`, applied via `NativeMenuEntry::owned_movie_patch` -> `patch_vr_native_art_movie`) | Same technique and hook: 12-byte rows `{path, size, offset, old, new, original_sha256, patched_sha256}`, chained per movie (each row pinned to the hash after the previous one). |
| Glyph art swap | `src/glyph_swap.hpp` | Separate, D3D side: watches texture binds (one-mip BC7 of a known glyph size) and substitutes the Quest labels. Keyed on the textures of `ui/lib_controller_buttons.raw.iggytex` (410128 B, 159 textures). |

### What the VR Settings edits actually are (decoded)

Pause menu (`PauseMenuData`, `PauseMenuScreen`), 5 edits per pause movie:
1. `PauseMenuData._initData`: one byte, `pushtrue` (0x26) -> `pushfalse` (0x27) after `pushstring 'ui_j_tab_stats'`.
2. `PauseMenuData._initMenuEntries`: 44 bytes; the list becomes resume, save, load, restart, options, **stats entry**, tutorials, quit (stats no longer conditional on `statsEntryAvailable`; freed bytes become `getlocal0; pop` pairs).
3. `PauseMenuScreen._onStatsClicked` (37 B): rewritten to `getlex GameService; pushstring 'VR_SETTINGS_EVT'; callpropvoid sendNotification 1; returnvoid` padding.
4. Pool string `ui_pause_devGUI` -> `VR_SETTINGS_EVT` (same length, 15 B).
5. Pool string `ui_j_tab_stats` -> `VR Settings   ` (14 B; an unknown localization key is shown verbatim). So the Stats entry is repurposed: its label is "VR Settings", its click sends the notification.

Main menu (`MainMenuData`, `MainHomeScreen`), 4 edits:
1. `MainMenuData._initData`: 59 bytes; the console-only Quit entry is re-added unconditionally right after Options (campaign, tutorial, options, **quit**, credits, DLC), removing the `Platform != PC` guard.
2. `MainHomeScreen._onQuit` (144 B): rewritten to `sendNotification('VR_SETTINGS_OPEN_REQUEST')`.
3. Pool string `ui_main_home_quitMessage` -> `VR_SETTINGS_OPEN_REQUEST` (24 B).
4. Pool string `ui_main_home_quit` -> `VR Settings      ` (17 B).

Back navigation needs `ui/lib_options.iggy` edits (in the glyph table, not `menu_patches.hpp`): `AbsOptionSectionScreen._BPressed` at 489418 becomes
`if (_data.instanceIndex < 100) return;` else `root._C_BackFromOptionSection()`, plus the jump rows at 293698 and 489430.

Glyph rows (`native_art_movie_edits`, about 40 movies): mostly one 4-byte row. In `ControllerButtonDefinition.getButtonImage` the branch
`10 79 00 00` (jump +0x79) becomes `10 5c 00 00` (jump +0x5c), so the method always takes the `image_XBOX` branch even after the VR pointer flips the
movie to mouse mode. Special rows: `hud.iggy` (`Crosshair_gun.<init>`, 12 B, the crosshair art), `quick_access_wheel.iggy` (wheel art, `ShortcutsHandlerWheel._updateShortcutsType`, `PotionsGamePad._onControllerChanged`), `lib_wheel.iggy`, `lib_options.iggy` (3 rows).

### How a patch is described and pinned
Offsets + same-length bytes + whole-movie SHA-256 before and after. `tools/gen_menu_patches.py` reads reviewed
`artifacts/menu-re/*.iggy.patch.json` manifests plus the extracted original movies, verifies old bytes and that the archived patched movie equals the
edits, and prints `src/menu_patches.hpp`. **`artifacts/menu-re/` (manifests and `abc.py`) is not present in this checkout**
(`tests/native_menu_patch_check.py` also needs it), so the D2 table cannot be regenerated here as is; for DOTO that does not matter (section 3).

## 2. Where the UI movies live

Neither install has loose `ui/*.iggy` files. Both keep them inside the resource archives, same container format
(`base/gameN*.index`, header `\x05SER`, plus `gameN*.resources`; entries are zlib-packed; two entries per movie: type `File` `ui/x.iggy` and type
`iggyFile` `ui/x.iggyfile`, same data; textures in `ui/x.raw.iggytex`). `tools/extract_arm_assets.py` (`index_entries`, `unpack_asset`) reads both.

* D2: `D:\Steam\steamapps\common\Dishonored2\base\game1*.index` (found by `tools/doto/target.py`'s Steam-library lookup from `targets/base.json`, `steam_folder` Dishonored2). Movie entries exist at every patch level (`game1` ... `game1_005`, `game1_patch`); the **last** (`game1_patch`) wins and its decompressed size is what the mod pins (`corvo_pause_menu.iggy` 518171 B, sha256 prefix `f4076445`, matches `menu_patches.hpp`).
* DOTO: `D:\Steam\steamapps\common\Dishonored_DeathOfTheOutsider\base\game1.index`, `game1_001.index`, `game1_patch.index` (`targets/doto.json`). One difference for any extractor: in DOTO `resource_id` is per index (id 0 in `game1_001.index` means `game1_001.resources`, id 1 in `game1_patch.index` means `game1_patch.resources`); `resource_path()` in `extract_arm_assets.py` (D2 numbering: 0 base, 1..5 `_00N`, 6 patch) returns the wrong file for DOTO. My scratch extractor tried the index's own container first, then the others, and accepted whichever inflated to the declared size. `tools/extract_game_art.py` needs the same fix if it is ever pointed at DOTO.
* The mod never reads the movie from disk: it patches the decompressed buffer the game itself loaded, inside the load hook. Ownership is "the bytes the game holds in memory", which equals the extracted size and hash.

### Is the patch structural, and can it be regenerated?
Yes it is structural (a small AS3 rewrite: reorder entries, repurpose a click handler, rename pool strings), but it uses only operand indices that
already exist in the movie's constant pool (the `GameService` getlex, the `sendNotification` multiname, the index of the string being renamed, the `_...Entry`
property multinames). So it is regenerable **by method name instead of by offset**: find the method bodies with the ABC parser, read the operand indices from
DOTO's own bytecode, and emit the same byte shapes. I implemented this as a proof of concept (appendix, about 80 lines on top of `tools/iggy_abc.py`):

* On D2's `emily_pause_menu.iggy` and `main_menu.iggy` it reproduces the shipped patched movies **byte for byte** (compared against `menu_patches.hpp` applied to the extracted originals).
* On DOTO it patches `emily_pause_menu.iggy` (flag at 345517, entries 345354, click 483484, strings 199993 and 199925; patched sha256 prefix `15ffd6cc`) and `main_menu.iggy` (entries 390946, click 510192, strings 237022 and 227500; prefix `6fc1cfb1`). Disassembly of the results shows the intended code: pause entries resume, save, load, restart, options, stats (= VR Settings), tutorials, quit with `_onStatsClicked` = `getlex GameService; pushstring 'VR_SETTINGS_EVT'; callpropvoid sendNotification 1`; main entries campaign, options, quit (= VR Settings), credits, DLC with `_onQuit` = `sendNotification('VR_SETTINGS_OPEN_REQUEST')`.
* Not yet generated: the DOTO `lib_options` `_BPressed` rewrite (needs the `_data` and `instanceIndex` multiname indices from DOTO's pool, same method) and the glyph rows.

Not verified (cannot be without the game): that the rewritten DOTO movies load and behave in the engine; that the DOTO load hook's manager layout is right (`tools/doto/offsets.json` records that `+0xa708` / `+0xa710` were confirmed by `fn_diff` for DOTO's `0x2f100`, but says nothing about the path at `+0xA608`, which should be checked with a read-only probe); and the native options page itself on DOTO's `lib_options`.

## 4. Port plan, effort, risks, fallback

Plan (each step is testable without a headset until step 5):

1. **Generator** `tools/doto/gen_menu_patches.py` (new; D2's generator untouched): promote the appendix PoC; extract DOTO's final-level movies with a DOTO-aware resource lookup; emit a DOTO edit table (`menu_patches_doto.hpp`, same `Edit` / `Movie` structs) with sizes and full hashes of original and patched movies for `emily_pause_menu` and `main_menu`. Add the `lib_options` `_BPressed` rows and the 4-byte `getButtonImage` rows (pattern search per movie, chained pins). Self-check: the same code run on D2 must equal the shipped table (already true for the two menu movies). About 1 day.
2. **Source integration** (the only `src/` change): `menu_patches.hpp` and `controller_glyph_atlas.hpp` need a per-game table switch (`#if D2VR_GAME_DOTO` or `game_profile.hpp`) so the D2 build stays byte-identical. `tools/doto/port.py` generates `build/doto-src` from `src/` and must not rewrite the table. About 0.5 day.
3. **Host-side check** (`tests/`): apply the table to the extracted DOTO movies, verify the patched hash, re-disassemble and assert the intended method bodies. About 0.5 day.
4. **Hooks**: confirm in DOTO that the translated load hook (0x2f100) hands over the movie buffer (`+0xA708` data, `+0xA710` size, `+0xA608` path) and that `NativeOptionsPage`'s Iggy API pins resolve. A read-only live probe of the manager struct is enough. About 0.5 day.
5. **Headset / sim verification** (needs the user's go-ahead for the live game): open the pause and main menus in DOTO, click VR Settings, change a value, go back (B), restore (X); check the 10-row limit and that the PC main menu shows one repurposed entry. About 1 day including fixes.
6. **Glyph rows**: `getButtonImage` rows first (low risk), then the hud crosshair and wheel rows (DOTO's `_onControllerChanged` needs a short review). About 1 day, independent of the VR Settings entry.

Total: about 3 to 4 days for the VR Settings entry with back navigation; glyph rows are a separate +1 day.

Risks:
* A game update changes the pins: both games fail safe (refuse, no entry); the generator makes re-pinning a one-command job.
* DOTO's `lib_options` differs (146 methods change length). The native page writes Iggy values by name and relies on `rowViewCount` 10 and the widget-pool fallback; identical behaviour is INFERRED and only a live check settles it.
* The pause patch removes the `statsEntryAvailable` gate, so DOTO's Stats screen is unreachable from the pause menu (same as D2).
* The main-menu Quit entry is repurposed (the PC build has no Quit entry anyway).
* Constant-pool u30 width: an index growing from 2 to 3 bytes would change code length; the PoC asserts every rewritten region keeps its length (all fit with DOTO's current indices).
* The label relies on the game showing an unknown localization key verbatim ("VR Settings   "), as in D2.
* Hash chains: glyph rows for the pause and main movies must be pinned to the post-VR-Settings hash, as in D2 (menus: VR Settings first), so row order in the table matters.
* Headset readability and comfort of the page are not established by any of this.

**Fallback if the port is not pursued (or fails safe):** launcher-only VR settings, as today (docs/DOTO-VR.md section 2): the launcher and proxy write the settings, the mod refuses the movies, the game menu stays vanilla, the hooks stay installed and inert. A mod-drawn panel (the retired GDI/ImGui path, `settings_panel_image.hpp` / `vr_menu_imgui.hpp`) is a possible in-game alternative but v1072 deliberately removed it as a fallback in D2.

## Appendix: proof-of-concept generator

Not committed; run with `python -I` next to copies of `tools/iggy_abc.py`'s directory on `sys.path`, from a scratch directory holding `d2/` and `doto/` copies of the
extracted `emily_pause_menu.iggy` and `main_menu.iggy` (plus `d2/<movie>.patched.iggy`, built from `menu_patches.hpp`, for the equality check).

```python

import iggy_abc as A
def u30(v):
    o=bytearray()
    while True:
        b=v&0x7f;v>>=7
        if v: o.append(b|0x80)
        else: o.append(b);return bytes(o)
def body(d,a,name):

def find_notify(d,a):
    c=collections.Counter()
    for m in a['bodies']:
        try: ops=A.dis(d,a,m)
        except Exception: continue
        for i,(at,op,x) in enumerate(ops):
            if op=='callpropvoid' and x.startswith('sendNotification 1'):
```
