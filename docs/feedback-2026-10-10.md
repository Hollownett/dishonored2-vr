# VR feedback implementation, 10 October 2026

The starting candidate is v193. Existing uncommitted Cloud/DeepSeek work is retained. Accepted movement and turning are protected. Dishonored 1 VR is the behavioral reference; its Unreal offsets and calling conventions cannot be copied into Dishonored 2's Void engine.

## Execution order

1. Keep controller hands and sword tracking during ordinary attacks and blocks. Relinquish to verified authored full-body actions only. Hide arm/forearm geometry and retain hands and equipment; arm calibration is deferred.
2. Resolve each hand's grip against its own fresh native selection before block. Keep physics pickup, native Interact, and combat ownership distinct. Add a visible ink cue with a target that matches the action and tracking frame.
3. Render VR settings within the actual pause-menu content, reached through the existing native VR Settings item. Investigate and implement world-space wheel and readable text presentation using verified native UI sources.
4. Verify FSR Native/Quality/Balanced dispatch, separate eye histories, resize/reset and fallback behavior. Add counters that distinguish selected FSR from successful execution.
5. Build a new version with source provenance, run focused and integrated checks, then exercise the real game with the existing simulated-controller tools. Promote only the verified result and retain v193 for recovery.

## Verification boundary

Automated/simulated checks can verify native routing, GPU output, lifecycle and restoration. They cannot establish headset appearance, wrist seams, comfort, combat feel, or complete gameplay. Those acceptance claims remain pending until the user checks the headset.

The launcher selects v199, with v193 retained as fallback. Existing Cloud/DeepSeek
work and save files were preserved. No headset session was started without the user.

- Ordinary blocks no longer hand the right wrist to native block animation.
  Controller wrist retargeting stays active for both hands. Only verified
  authored actions take native hand ownership. Hands-only mode hides upper arms
  and forearms, bypasses full-arm calibration and suppresses its startup prompt.
- Physics pickup now distinguishes native carrying from equipped weapons,
  allowing either armed hand to grab. Native Interact locks its pointing hand
  through the grip, waits for that hand's fresh completed selection, invalidates
  on owner/epoch changes, and has priority before fallback sword block.
- The ink cue follows the same eligible target as pickup, caches bounded reads,
  revalidates identity, and disappears for occupied/held/authored states. The
  native interaction ray ABI was verified: entity output and float distance
  output are separate; the entity output is never interpreted as a hit point.
- Native Pause > VR Settings opens settings inside the native menu image,
  preserving navigation outside the content rectangle. The controller uses the
  same menu pose and rectangle for selection. The independent settings XR layer
  was removed. Repeated native-menu hook installation now reuses owned hooks.
- Wheel, journal and notes are classified by exact movie paths and owner
  identity. Isolated native UI art is recorded on the native deferred context
  and published after matched command-list execution. It is submitted as a
  world panel over tracked stereo scene rendering. Wheel pose freezes on open;
  journal/notes follow the left hand. Movement and combat remain gameplay-gated.
- FSR handles independent eye histories, resets, resized targets, stale jobs,
  split deferred command lists and native TAA fallback. Success and fallback
  counters make actual execution observable. The reused native shot hook was
  also repaired so later sessions no longer fail duplicate creation.

## Verification

`tools/build.ps1 -OutputName d2vr_render_probe_arm_v199.dll` completed the full
MSVC/focused Python/C++/GPU pipeline. The source stayed unchanged throughout the
build. It was archived before compilation, not compiled from a frozen snapshot.
Provenance: `artifacts/build-source/20261010T102233.610626Z-5dadd84a`;
log: `artifacts/feedback-build-v199.log`.

The pipeline includes independent blocking/hidden-segment and native palette
fixtures; two-hand query/grip freshness and arbitration; actual WARP UI alpha,
render target preservation, deferred completion, resizing and lifetime checks;
native menu/shot hook reinstallation; settings composition and portrait layout;
and a 1,000-frame simulated XR lifecycle/resource test. FSR GPU checks cover
Native, 77% Quality and 67% Balanced, immediate/deferred paths, padded LDR
subrects, resize/reset and oversize rejection. Compared outputs were within
0.001. The D3D debug layer was unavailable in that standalone check.

Final live trials all use the pinned Steam executable, actual native game/GPU,
simulated controllers and the exact v199 DLL. These are not headset sessions.

All these final trials reported zero first-chance fault records, recoverable
faults, callback failures, FSR creation failures and FSR dispatch failures.
Hooks, camera comfort and session settings restored on exit. FSR counters are
cumulative within a loaded DLL: the table reports differences between runs.
Quality/Balanced also recorded 598/603 skipped upscale jobs; this is evidence of
successful execution, not a claim that every frame used FSR. Native mode had
successful dispatches for both eyes in the preceding final trials.

Settings composition at 1273x701 changed 347,406 pixels inside
`[53,123,637,546]`; outside pixels had maximum delta zero. This proves composition
into the same native menu image. Isolated wheel/journal textures retain the
native artwork's grain/vignette and alpha, without the hallway scene.

Both pickups acquired native prop `262540224` at approximately 0.0900 native
units contact gap and held it for 2.937 seconds, with at most 16 ms between
motor samples. Actual vertical travel was 0.0311/0.0354 against a commanded
0.18 lift. The prop is in a cabinet and collision remains native; the cause of
limited travel is not established. These runs prove acquisition, maintained
ownership and release, not unrestricted lift fidelity or throwing. Sword and
pistol were visible in the game; equipment tracing was not enabled for these
runs. Native interaction selection traces did not capture a selected Use
target, so door/loot Use remains a live acceptance check.

An intermediate v195 wheel trial crashed. It was preserved and excluded from
promotion. The final capture path validates the real D3D context, records on the
owned deferred context and avoids calling Present's immediate context from the
UI worker. Subsequent v196-v199 trials completed without the observed failure.
Retired capture RTVs intentionally remain retained until game exit because
Iggy caches raw pointers; repeated resolution changes can retain small resources.

## Return to play

Run `.\tools\run_demo.ps1 -Launch` after connecting the headset. The saved AA
choice was Off; it is now FSR Native. All other saved fields, including snap
45 degrees, smooth speed 90, resolution 1, HUD 65%, sharpening and mirror mode,
were preserved. Original preferences are in
`artifacts/feedback-vr-settings-before.cfg`. Temporary `build/aa-mode` diagnostics
were removed. Change FSR mode through Pause > VR Settings.

fixture recorded 13 guarded body-identity/bounds rejections; this is separate
from the explicit scripted trials above. That fixture is excluded from the
normal headset path. The game is left paused with VR stopped, without writing
a manual save.

Headset checks still need to cover hand/wrist appearance, controller block feel,
ink visibility and natural reach, free-object motion/throwing, door/loot Use,
separate notes, wheel selection/readability, settings at headset portrait
resolution, FSR image quality and frame pacing, authored action handoff,
loading/focus/death transitions and complete gameplay. These checks are not
claimed complete by the simulated trials.
