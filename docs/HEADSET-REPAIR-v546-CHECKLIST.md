# v546 repair acceptance gates

This is an acceptance checklist, not a passing result. The candidate stays launch-blocked until its runtime prerequisites are met. Preserve numbered builds, accepted locomotion/turning, shared saves and the exact loaded DLL/PID/source archive.

## Before gameplay

1. Confirm the complete required build and source identity of the exact candidate; focused fixtures alone are insufficient.
2. Establish a contained runtime lane with actual native gameplay and checkpoint reload. The no-Steam private lane rejects this retail checkpoint before map activation; do not patch the save/header/predicate or silently enable Steam/cloud access.
3. Start a fresh game process. This repair prevents future shared tuning writes; it does not repair unknown values left by an older DLL in the same process or save.
4. Keep the candidate manifest blocked until these prerequisites and the remaining implementation gates are resolved. Do not use the older default development manifest as a bypass.
