# v221 body repair: source evidence and integration

User observations: v220 calibration displaced the avatar, hands/joints misaligned, aiming hand disappeared, legs trailed even before calibration. These changes require headset acceptance.

## Confirmed causes repaired

- `Driver::solve_locked` limited elapsed time to 1/30 second; at 10/5 Hz gait advanced at only 1/3 or 1/6 wall time. It now consumes monotonic elapsed time with interpolated head/hand substeps no larger than 1/30 second, at most 15 substeps for normal intervals. Gaps over 0.5 second or a non-increasing supplied tracking tick reset temporal state and replant instead of replaying the missing interval. Reference changes and calibration transitions reset the elapsed baseline. The solver's independent 0.1 second cap is respected by every substep.
- `Driver::arm` returned the previous body output after a new tracking publication. It now rejects unmatched tracking revisions and publications older than 250 ms, preserving caller native fallback. Arm-before-body rejection is explicit (`ArmGate`). No speculative solve uses an old body model frame.
- Calibration previously changed local spine03/neck Z assuming these were world vertical, despite rotated native joint bases, and measured eye drop to chest rather than the shoulder landmarks. Fit translations now use inverse parent rotations and the actual world-bind upper-arm shoulder midpoint. Shoulder span also uses those world-bind landmarks instead of arm-model Y/local Y. Tests require the requested dimensions and unchanged camera position.

- Palm-span fit no longer multiplies the fixed wrist/palm landmark offset by limb scale. Driver subtracts that fixed offset from the requested palm span; BodySolver solves the limb-only span equation rather than counting hand geometry in the scalable reach. Configured bind palm span is reported and checked against the requested fit (including v220 accepted dimensions).

The accepted v220 fit event is CSV event 32, tick 225335234, Present 21555, reference/pose epochs 1. Native palm span 1.46747 m, shoulder span 0.311208 m, accepted arm scale 1.06811, eye-to-shoulder 0.148397 m. No measured floor is present; do not imply the native model origin is a verified XR floor. Acceptance still reconstructs the solver; we do not silently invent a standing height.

## Production integration for coordinator

Set the new `fullbody::Tracking::tick` from `hands.tick` (monotonic milliseconds), `tracking_revision` from the frozen arm publication revision and `native_frame` from the exact native/render frame identity available at publication. Omitting tick uses steady-clock wall intervals; the metadata fields do not change accepted locomotion/turning. Preserve owner/model invalidation calls to `clear()` and reference epochs.

`Driver::diagnostic()` returns one mutex-consistent bounded value copy: tracking, internal/external revision, fit revision/dimensions, callback serial/order, actual elapsed/consumed/substep dt, gap reset, solution age, native model frames, scale/limb scale, grip-to-attachment transforms, target attachment poses, gait phase/planted/swing endpoints and authored weights. Returned palette landmarks are reconstructed from the actual model-local transforms returned by `body()`/`arm()`, through the same supplied native frame: final pelvis/ankle and wrist/palm. Palm uses returned wrist and four named MCP joints with production `hand_bind_grip`; its residual compares the same world frame against the intended grip/palm target. `body_valid`/`arm_valid` are reset on publication, and become true only when that consumer obtains a replacement. These are palette receipts, not proof the consumer actually draws visible geometry.

Call this accessor after the relevant owned native consumer call and attach owner IDs, receipt/palette hashes, tracking flags/reference type/prediction time, culling/material gate outcomes and hook durations in the coordinator's synchronized observer. `arm_gate` distinguishes no output, revision mismatch and age rejection. Root must preserve native authored fallback and record that alternative consumer's final palm too: this Driver snapshot cannot attest the ArmTracking fallback palette. No native hooks, offsets, calling conventions, material transaction or ownership policy were changed here.

## References and limits

Existing `docs/full-body-research.md` and generated native rig fixtures verify Z-up metre world coordinates, rotated native local binds, chest arm attachment and model/world frame conversion. Primary mathematical reference: https://raw.githubusercontent.com/id-Software/DOOM-3/master/neo/game/IK.cpp (two-bone IK and explicit model coordinates); it supplies no Void ABI evidence. Changes are pure owned math and renderer palette copies.

Remaining causes: no measured floor under the avatar; native nonuniform/model scale ownership is not rederived; final skinning inverse-bind scale, material visibility/culling and exact callback ownership remain independent gates. Native authored arm palettes can remain cached across frames until callbacks refresh them; current ownership does not prove same-frame native animation. These changes neither explain all hand disappearances nor establish headset alignment, comfort or performance.
