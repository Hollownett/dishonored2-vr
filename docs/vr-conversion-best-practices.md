# Flat-to-VR Conversion Best Practices (research digest for the Dishonored 2 VR mod)

Distilled from the flat-to-VR modding community (UEVR/REFramework/Luke Ross/Flat2VR), native VR ports and their mod ecosystems (HL2:VR, Skyrim VR + VRIK/HIGGS/PLANCK), and platform design guidance. Each rule links to a source; "safest for a first iteration" is marked **(default)**. Core sources: [UEVR docs](https://docs.uevr.io/print.html), [HL2:VR](https://halflife2vr.com/features/), [HIGGS](https://www.nexusmods.com/skyrimspecialedition/mods/43930), [PLANCK](https://www.nexusmods.com/skyrimspecialedition/mods/66025), [VRIK](https://www.nexusmods.com/skyrimspecialedition/mods/23416), [REFramework VR](https://reframework.dev/unlocking-virtual-reality-with-reframework/), [Until You Fall GDC](https://gdcvault.com/play/1026868/Until-You-Fall-Building-Satisfying), [comfort stack](https://zenodo.org/records/16755903/files/Riecke_2025_-_VR_Comfort_Stack_Preprint_and_slides.pdf?download=1).

## 1. Rendering & comfort

- **Never move the camera the player did not move.** All head motion comes from tracking; game code may move the *player body*, never the view. UEVR's design rule is that camera control belongs to the runtime, and the mod only offsets it deliberately ([UEVR docs](https://docs.uevr.io/print.html), [UObjectHook](https://docs.uevr.io/usage/adding_6dof.html)).
- **Prefer the engine's true stereo path.** Native stereo keeps temporal effects intact, and DLSS/FSR2 "work completely fine with no ghosting"; sequential/AFR modes reintroduce TAA ghosting and must disable motion blur. Treat sequential as the fallback, not the target ([UEVR rendering modes](https://docs.uevr.io/print.html)).
- **Never use alternating-eye rendering for gameplay.** AFR desynchronises the eyes and "usually" causes nausea — only for menu/paused states at most ([UEVR rendering modes](https://docs.uevr.io/print.html)).
- **Keep the game's tick in lockstep with the eye pair.** Two views must be rendered from one simulation state; time may not advance between eyes ([UEVR rendering modes](https://docs.uevr.io/print.html)).
- **Treat TAA as a stereo hazard, not a preference.** If the mod forces sequential rendering, expose TAA/motion-blur/sharpening toggles and prefer temporal-disabled or MSAA-style AA in VR ([UEVR troubleshooting](https://docs.uevr.io/print.html)).
- **Frame pacing beats resolution.** If you cannot hold refresh with headroom, lower render scale before cutting refresh; runtime reprojection/ASW/SSW is a safety net, not a budget. Do not let a 60 Hz-locked game trip the runtime into halving the frame rate ([UEVR troubleshooting](https://docs.uevr.io/print.html), [R.E.A.L./VRto3D profiles](https://github-wiki-see.page/m/oneup03/VRto3D/wiki/Luke-Ross-RealVR-Mods), [Meta comfort guidance](https://www.uploadvr.com/meta-ideal-vr-session-length-20-40-minutes/)).
- **Enable depth submission when available** so the runtime's late-latching/reprojection can use correct depth (UEVR's `VR_PassDepthToRuntime` improves OpenXR latency) ([UEVR docs](https://docs.uevr.io/print.html)).
- **Do not fight the runtime for latency**: disable frame-generation, keep `r.OneFrameThreadLag`-class pipeline buffering off, and stay on the runtime's native API for rotation (OpenXR over OpenVR on Virtual Desktop) ([UEVR latency notes](https://docs.uevr.io/print.html)).
- **Offer comfort options up front**: snap and smooth turn, decoupled pitch/horizon lock, teleport alternative, and vignette/fade when the head intersects geometry ([UEVR motion sickness notes](https://docs.uevr.io/print.html), [HL2:VR comfort features](https://halflife2vr.com/features/), [VR comfort stack](https://zenodo.org/records/16755903/files/Riecke_2025_-_VR_Comfort_Stack_Preprint_and_slides.pdf?download=1)).
- **Filter camera shake on vehicles/scripted rides** and keep the horizon upright; HL2:VR filters airboat bumps and adds a third-person/decoupled fallback for players who cannot stomach it ([HL2:VR features](https://halflife2vr.com/features/)).

## 2. Body & hands

- **Hands-only is the correct first target; full body is an upgrade.** Floating hands (with optional finger poses) are the shipped norm for conversions; full-body IK like VRIK is a separate, later feature because it needs a calibrated skeleton and prone/crouch/ladder handling ([HL2:VR features](https://halflife2vr.com/features/), [VRIK](https://www.nexusmods.com/skyrimspecialedition/mods/23416)).
- **One owner per hand per frame.** Decide explicitly whether the tracked controller or the game's animation owns each hand; two writers produce jitter and popping. Drive arms with IK toward controller targets, never with two competing transforms ([VRIK](https://www.nexusmods.com/skyrimspecialedition/mods/23416), [FinalIK VRIK reference](http://root-motion.com/finalikdox/html/class_root_motion_1_1_final_i_k_1_1_v_r_i_k.html)).
- **Hand control back during scripted moments** — vaults, finishers, takedowns, climbing, cutscenes, and possession/Blink-style sequences must temporarily detach the hands and let the authored animation play, then blend back. This is the standard solution to "my arms are in the wall during a takedown" ([VRIK](https://www.nexusmods.com/skyrimspecialedition/mods/23416), [HL2:VR features](https://halflife2vr.com/features/)).
- **Keep hand poses cheap**: idle/fist/point/grip poses plus Index finger tracking if available; full per-weapon animated hands are explicitly a "gradually added" feature ([HL2:VR features](https://halflife2vr.com/features/)).
- **Align weapon to hand, not hand to weapon**: parent the weapon to the dominant hand socket with tuned offsets; support off-hand grab for stabilisation ([HL2:VR](https://halflife2vr.com/features/), [UEVR UObjectHook](https://docs.uevr.io/usage/adding_6dof.html)).
- **Model occupied hands** (carrying a body, interacting) as a real state that blocks grabs/attacks and disables that hand's aim ray ([HL2:VR features](https://halflife2vr.com/features/), [HIGGS grab rules](https://www.nexusmods.com/skyrimspecialedition/mods/43930)).

## 3. Input & interaction

- **Use the community-standard console layout.** UEVR's defaults are the de facto convention: left stick = move, right stick = rotate, grips = LB/RB, triggers = LT/RT, stick click = L3/R3, face buttons mirrored as Xbox ([UEVR default bindings](https://docs.uevr.io/usage/vr_controller_bindings.html)). Our virtual-gamepad remap should match this so muscle memory transfers.
- **grip = grab/steady, trigger = use/shoot.** HIGGS/PLANCK make grip the grab button and trigger the "operate" button; the ecosystem trains users otherwise ([HIGGS](https://www.nexusmods.com/skyrimspecialedition/mods/43930), [PLANCK](https://www.nexusmods.com/skyrimspecialedition/mods/66025)).
- **Put crouch on stick-down (L3/R3) with a toggle**, and physical crouch as an alternate; stick-click is the least-used ergonomic slot in the standard layout ([UEVR default bindings](https://docs.uevr.io/usage/vr_controller_bindings.html)).
- **Holster on a deliberate, non-adjacent input** (shoulder/hip gesture or face button), never the same button as grab or attack — that ambiguity is the classic cause of accidental swings ([HL2:VR](https://halflife2vr.com/features/), [HIGGS](https://www.nexusmods.com/skyrimspecialedition/mods/43930)).
- **Quick menus/wheels belong in front of the pointing hand**, opened by stick click or a face button, selected by hand pointer or stick. HL2:VR adopts Alyx's hand-anchored weapon wheel for exactly this reason ([HL2:VR features](https://halflife2vr.com/features/)).
- **Remove accidental-action ambiguity with states, not timers alone.** HIGGS' grab checks require sustained proximity, not one frame, before a grab fires; mirror that hysteresis/grab-radius discipline for grab-vs-attack ([HIGGS changelog](https://www.nexusmods.com/skyrimspecialedition/mods/43930)).
- **Every gesture needs a button fallback.** Gesture-only binds (holster, rearm, head-tap flashlight) fail for seated players, injuries, and unreliable hand tracking — HL2:VR keeps flashlight as a head-tap *and* a binding, and all binds are rebindable ([HL2:VR features](https://halflife2vr.com/features/), [SteamVR Input](https://partner.steamgames.com/doc/features/steamvr/input)).

## 4. Aiming & combat

- **Shoot from the weapon/hand ray, and reuse the game's real aim solver.** One authoritative ray per hand/weapon drives the crosshair, hitscan, projectiles and powers; never let a cosmetic laser and the game's damage ray diverge ([UEVR UObjectHook/attachment practice](https://docs.uevr.io/usage/adding_6dof.html), [HL2:VR weapon handling](https://halflife2vr.com/features/)).
- **Keep the game's crosshair first, but move it onto the hand ray**; add an optional laser/dot for hip-fire as a toggle, keeping the reticle the game already tunes ([HL2:VR](https://halflife2vr.com/features/), [Until You Fall GDC](https://gdcvault.com/play/1026868/Until-You-Fall-Building-Satisfying)).
- **Melee = motion + velocity threshold + cooldown.** A swing counts only above a minimum angular/linear speed, then enters a short cooldown; this is how VR melee games stop "wiggle-spam" and reward real swings ([Until You Fall GDC](https://gdcvault.com/play/1026868/Until-You-Fall-Building-Satisfying), [VR slash-experience study](http://www.interaction-ipsj.org/proceedings/2022/data/pdf/6D11.pdf)).
- **Block/parry should be an explicit held pose** (weapon up + grip), evaluated before attack, with the same thresholding as swings, so raising your guard never triggers a swing ([Until You Fall GDC](https://gdcvault.com/play/1026868/Until-You-Fall-Building-Satisfying)).
- **Make physics read as hits**: micro-hitstop, haptics scaled by impact energy, weapon recoil/torque, object reaction; HIGGS/PLANCK exist because believable physics drives presence ([PLANCK](https://www.nexusmods.com/skyrimspecialedition/mods/66025), [VR presence](https://www.uploadvr.com/importance-believable-vr-hands-presence/)).
- **Give haptics an explicit priority/ownership model** (hit > swing > UI tick) and drive them from the same event that spawns the damage, so feedback never disagrees with the combat result ([Until You Fall GDC](https://gdcvault.com/play/1026868/Until-You-Fall-Building-Satisfying)).

## 5. UI / HUD

- **World-anchored > wrist-anchored > head-locked.** Auto-project existing HUD into 3D space where possible (UEVR does this for most in-game UI); reserve head-locked elements for tiny, momentary status only ([UEVR features](https://docs.uevr.io/print.html), [cross-platform interaction guidance](https://immersive-insiders.com/blog/create-interactions-that-work-cross-platform)).
- **Menus on quads in front of the player, not glued to the face**; UEVR projects UI into 3D space and lets the player point at it with a motion controller ([UEVR features](https://docs.uevr.io/print.html)).
- **Size text by angular size, not pixels.** Keep important text above ~0.6° vertical angular height at its real distance, put menus 1.5–2.5 m out, and use high-contrast, non-thin fonts ([legibility study](https://pure.unamur.be/ws/portalfiles/portal/92390953/2024_CauzM_these.pdf), [Meta comfort guidance](https://www.uploadvr.com/meta-ideal-vr-session-length-20-40-minutes/)).
- **Show VR controller glyphs, not keyboard/Xbox prompts.** UEVR testers explicitly added Oculus controller prompts per game because inherited prompts break immersion and learnability ([UEVR acknowledgements](https://docs.uevr.io/print.html)).
- **Cutscenes on a virtual screen** (a world-anchored quad or a theatre plane) so the authored camera does not drag the player's head; this is the standard comfort fallback for non-VR cinematic cameras ([HL2:VR vehicle/camera fallbacks](https://halflife2vr.com/features/), [UEVR comfort notes](https://docs.uevr.io/print.html)).

## 6. Engineering practices for mods

- **Pure policy modules with host-side tests.** Keep hit-testing, thresholding, holster/crouch state machines and input arbitration in pure functions, unit-tested outside the game; keep only transform reads/writes in the injected layer ([UEVR plugin system](https://docs.uevr.io/plugins/getting_started.html), [UEVR C++/Lua plugin model](https://docs.uevr.io/print.html)).
- **One aim ray, one source of truth.** Export a single aim-ray function used by crosshair, projectiles, powers and grab; duplicated ray math is the most common source of "my shot went where I wasn't aiming" ([UEVR UObjectHook practice](https://docs.uevr.io/usage/adding_6dof.html)).
- **Per-feature toggles + per-game config persistence.** Every risky feature (hand aim, motion melee, physical grab, TAA override, UI projection) ships on/off, and configs persist per title ([UEVR per-game configuration](https://docs.uevr.io/print.html), [UEVR overview](https://docs.uevr.io/usage/overview.html)).
- **Fail closed.** If a hook, pointer or pose sample is missing, fall back to the flat behaviour (gamepad-driven, head-locked prompt) rather than writing zero/invalid transforms into the engine ([UEVR compatibility modes](https://docs.uevr.io/print.html), [UEVR UObjectHook caveats](https://docs.uevr.io/usage/adding_6dof.html)).
- **Instrument counters.** Track grabs attempted/granted, swings rejected by threshold/cooldown, hand-backs, ray-disagreement events and dropped frames; the only way to tune thresholds without guesswork ([HIGGS changelog](https://www.nexusmods.com/skyrimspecialedition/mods/43930), [UEVR callbacks](https://docs.uevr.io/plugins/lua/callbacks.html)).
- **Build a simulated runtime** so the mod can run headless (scripted poses/buttons) before a headset; simulation proves logic only, never visual quality or comfort ([UEVR Lua API](https://docs.uevr.io/plugins/lua/api.html)).

## Applies to our D2 mod now

- **TAA ghosting**: stop assuming the stereo path is clean; add a runtime TAA/motion-blur toggle and prefer a reprojection-safe AA path; verify per-eye with the R.E.A.L./UEVR sequential-mode warning as the failure signature.
- **Hand-aimed weapons**: route the existing weapon aim solver through one exported aim ray instead of leaving the flat camera ray authoritative.
- **Native crosshair on hand**: relocate the game's crosshair to the hand ray and keep a laser/dot as an optional toggle — do not build a second, parallel reticle.
- **Holster / weapon-up-down**: bind holster to a gesture or face button, never to the same input as grab or attack; keep a button fallback for seated play.
- **Grab vs attack**: add hysteresis/grab-radius checks and an explicit state priority (grab < block < attack) so a near-object interaction cannot eat a swing.
- **Occupied hands**: define a hand state machine (free/gripping/occupied-by-carry/scripted) and let it gate grab, attack, aim and haptics.
- **Finisher / takedown hand-back**: detect finisher/takedown/possession animations and suspend hand ownership, blending back after the animation releases control.
- **Full arms**: ship calibrated arm IK only after hands-only works; leave a "hands only" fallback because VRIK-class body IK needs a skeleton and crouch/prone handling we do not have yet.
- **VR glyph prompts**: replace inherited keyboard/Xbox prompts with Quest/Index glyphs; this is a low-cost, high-visibility win (UEVR added per-game controller prompts for this reason).
- **Head-following menus / cutscene screen**: convert head-locked UI into world-anchored quads placed 1.5–2.5 m out, and put non-VR cinematic cameras on a virtual screen.
- **Crouch**: put crouch on stick-click with toggle, plus optional physical crouch, instead of a keyboard-style key.
- **Comfort set**: confirm snap/smooth turn, decoupled pitch, teleport option and intersection fade are all present and persisted per config.
- **Frame pacing**: expose reprojection/SSW as a safety net and verify the game is not 60 Hz-locking the runtime into halved frame rates.
- **Telemetry**: emit the grab/swing/hand-back/ray-disagreement counters above before tuning any threshold.
- **Tests**: move grab/attack arbitration, holster state and threshold policy into host-testable pure modules driven by the simulated runtime.
