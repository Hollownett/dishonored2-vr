# v547 controlled repair-test gates

This is a staged acceptance plan, not a passing result or a release claim. Keep the existing v546 and all older numbered DLLs. A fresh v547 may only be produced after the complete required build passes with unchanged archived inputs. The default candidate manifest remains untouched. Never inject into an already tested or historically modified process merely to avoid a fresh launch.

## 1. Implemented source and offline evidence

- Preserve accepted locomotion, turning and VR entry/exit. Current accepted body/arm output replay matches the pre-refactor baseline exactly across 240 deterministic records; this does not establish in-headset appearance.
- Door ownership now uses the composed native controller, including slow partial reversal and physical closing. Native owned-arena composition passes; actual game scheduling, linked doors, scripted takeover and visible door feel remain unaccepted.
- Clear/stop now revoke paired anatomical admission across owner ABA and drain admitted callbacks. Native Grab has a non-reset lifecycle revision so clear/reinstall cannot revive an old empty-hand lease.
- Raw anatomical hand sampling is **shadow-only and disabled by default**. `build/anatomical-shadow` requires full-body, tracked arms, synchronized diagnostics and installed interaction/Grab owners. It samples a matching pair of 24 actual palette proxies, at most ten pair attempts per second, with current Source and empty-hand checks. It never changes hand palettes or authorizes response. The old palm clamp is still active.
- Target root sphere/capsule surface receipts and actual native traversal labs remain diagnostic prerequisites, not asynchronous shape lifetime/ABA authority. Mesh/compound collision response is not certified.
- v546's mutation-free Choke and exception-cleanup repairs are retained. No shared declaration normalization or widened Kill cache policy is introduced.

## 2. Runtime prerequisites

Normal Steam was launched without VR under PID40120; the user confirmed checkpoint load and reload both work. This separates the retail checkpoint from the private no-Steam lab's platform refusal. It does **not** validate VR reload or prove private save/cloud isolation.

Leave that interactive process under user control. Before VR testing, agree on a fresh Steam session and exact candidate, preserve saves and settings without overwriting originals, and record the loaded DLL hash, PID, arguments and source archive. No Steam/cloud/backend change or private-lab bypass follows from the normal-load result. Do not remove launch blocks or use the older default manifest as a workaround.

## 3. Short headset sequence

Stop immediately on a crash, severe stutter, unexpected movement, save issue or loss of VR exit. Preserve logs before another attempt.

| Feedback | Required acceptance |
|---|---|
| Reload crash | At least five same-process death/checkpoint reload cycles, then another save/map transition; exact loaded candidate and crash/observer trace retained. Normal Steam success is only the baseline. |
| Oversized hand sphere | Both palms/fingers at walls and props, open/half/fist and slow/fast contact. Shadow records are evidence only; the old clamp means this defect is not declared fixed. |
| Grip Talk becomes choke | Talk, shops and offered Use targets win until release; deliberate unaware-target choke commits once; no trigger/grip leakage. |
| Severed head/arm far from hand | Visible object mesh stays at the intended grasp through carry, turn, crouch, release and reacquisition; counters alone do not pass. |
| Hip gun attachment | Holster and draw zone follow pelvis through head movement, crouch and turning, without moving accepted locomotion/perspective. |
| Blade does not block | Actual incoming damage is blocked with the blade in front, including small parry motions; attack, pistol and power behavior remain intact. Hook eligibility alone does not pass. |
| Thrown sword floats | Aware/unaware targets, wall and floor impact, including kill and release; no delayed freeze or floating weapon. |
| Gentle doors jitter / cannot slam shut | Both swing senses, gentle push, partial reversal, fully open closing/slam without trigger, and locked/scripted/linked leaves; no jump or double writer. |

## 4. Performance and completion

Compare the same scene with shadow off, and only then opt in to a short shadow capture if prerequisites and runtime cost permit. Record contiguous worst-case gameplay windows and headset/compositor timing; median or predicted display period is insufficient. Shadow JSON describes its own older request/frame/tracking sample, not necessarily the surrounding uploaded palette.

Only actual headset acceptance can close visual quality, comfort, calibration, body/weapon rendering and gameplay gates. Until all feedback and runtime/performance gates pass, `release_ready` and `headset_acceptance` remain false. Do not call this build bug-free.
