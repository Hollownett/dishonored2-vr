# v221 interaction repair evidence

The v220 user observations remain the acceptance baseline: unreliable intended pickup, missing/wrong/flat prompts, drifting markers, oversized health/ammo/reticle, and right-eye obstruction while carrying. Two successful coins do not accept the complete system.

## Implemented changes

`NativeGrab::focus_body` no longer copies/walks all 0x3fff entity registry slots synchronously. Per hand, `NativeGrabDiscovery` advances 256 slots once per new pose-publication tick and retains at most 64 nearby dynamic candidates. Every retained candidate is revalidated with the existing full `native_rigid_body` ownership routine; entity spawn, component identity, body handle, model and world must still match. Near candidates remain in the cache while hands move, with current geometry refreshed at each publication. The complete registry takes 64 slices; newly spawned or newly approached objects may require that discovery interval. Selection and acquisition independently revalidate lifetime. Native Use, authored carrying and the opposite held hand retain ownership priority. Physical acquisition additionally checks cached world and full entity spawn identity.

Native Use fetch telemetry distinguishes incomplete, empty, single, multiple and rejected outputs. The pinned return convention and record layout are unchanged. Only accepted multiple-hit buffers are reordered; a single or empty result is no longer misreported by a zero sort counter. Native permission, range, character classification and LOS remain authoritative. Existing blocked-object scan continuation preserves the original rejected result and gives another object its own native checks.

`live_target` applies a common fresh selected-hand/revision gate and revalidates native component generation, owner spawn registry, current player/camera and authored-camera refusal. Prompt target-side, identity, anchor and per-hand availability use it. `qualified_target(now)` exports identity and optional static-model surface anchor together under one lock, with source publication/selection timestamps and final lifetime revalidation. Root must convert that anchor with the matching render/reference frame, and only suppress the native flat child after the existing both-eye replacement acknowledgement.

Both interaction classes expose bounded diagnostic snapshots through try-lock accessors. NativeGrab reports the source epoch/tick, focus/held complete identity, acquisition time, discovery cursor/cache/slices/lifetime rejections and cumulative/max CPU focus microseconds. NativeInteractionAim reports selected component, generation, source publication/selection tick, epoch, routing/ready revisions, qualified state and query-outcome counters. A skipped snapshot is missing evidence, not a failed interaction. Separate class snapshots retain separate timestamps and do not claim to be one atomic engine frame.

## Root integration

- Read `NativeInteractionAim::diagnostics(now)` and `NativeGrab::diagnostics()` from the bounded synchronized observer. Query outcome array order is `incomplete, empty, single, multiple, rejected`.
- Use `qualified_target(now)` when pairing captured prompt identity with its world anchor; `point` is optional and must not be substituted by an unrelated ray or physics hover.
- Apply requested half-size health/ammo once at wrist physical layer: `game_xr.hpp` native wrist `pixel_scale` changes `.22f` to `.11f`, before `native_panel_fit`. Keep native crop/canvas pixels, both-eye containment and all image/state retirement safeguards.
- `NativeCrosshair` has verified X/Y setter members only. Reticle sizing needs a proved isolated native child/asset path. No unproved AS3 scale member or whole-HUD shrink is added here.
- Native marker packets currently carry a freshness tick, while world transform carries a render frame. Root must associate the native marker callback with the actual render frame/epoch when recording/presenting the packet. Arbitrary timestamp equality is not a valid frame-identity proof.

## Offline checks and remaining acceptance

`native_grab_compile` now checks bounded per-publication discovery, no repeated scan on the same tick, registry wrapping, destroyed/recycled entity removal and existing either-hand grip/native-action priority. `native_use_order_check` now distinguishes the five fetch outcomes and malformed bounds, in addition to adjacent loot ordering, full-record preservation, stable ties and failed native LOS/permission cases. Existing native hook passthrough/range/two-hand checks remain required.

These CPU fixtures do not prove actual native overlap delivery, physical-grab LOS, guard action semantics, carrying stereo, headset attachment/size or user intent. The dynamic physical selector still has no separately proved native LOS seam; do not describe its lifetime checks as LOS approval. Guards must retain native action/carry behavior; generic physics grabbing cannot repair choke/kill prompts. Right-eye carrying obstruction remains an unresolved geometry/render ownership defect requiring synchronized live evidence. No live game, GPU, headset or save control was performed by this track.

## Native wheel glyph and gun reticle movie repair

The archived v220 `glyph_swaps=0`, `glyph_identified=0`, `glyph_checked=14`, mask0 do not establish that all texture replacement failed: the separate creation hook had already recorded 30 replacements. They measure different paths. More importantly, controller movie `getButtonImage` takes the PC keyboard-equivalent branch when controller type is keyboard/mouse; substituting Xbox BC7 textures cannot affect those text glyphs.

Read-only installed-resource extraction identifies the current wheel movies by complete SHA256 in `artifacts/research/interaction-v221/native-art-movie-patches.json`. Their embedded `ControllerButtonDefinition::getButtonImage` now starts at its existing Xbox bitmap branch through one same-size jump edit in each of `ui/quick_access_wheel.iggy` and `ui/lib_wheel.iggy`. Native bitmap naming, large/small suffix, null handling and artwork ownership remain intact. The existing Quest label substitution sees those Xbox glyph resources; unrelated menu/controller libraries are unchanged. Actual wheel appearance still needs a live owned-load and headset check.

The exact shipped HUD `Crosshair_gun` constructor has two graphical radius initializations that its own dispersion setter never uses: that setter calls `getDispersionRadius`, whereas the only other `getGraphicDispersionRadius` call is in the independent crossbow class. The 12-byte unused gun-only initialization block becomes native public `scaleX=scaleY=.5` assignments using existing ABC pool entries. Arc art, alpha, animation/state and dispersion input remain native; the root gun visual scales once around its own origin. The surrounding HUD, damage vignette and crossbow class bytes are unchanged. This is a same-size native movie change, with no invented C++ property handle or procedural reticle.

`patch_vr_native_art_movie(path,data,size)` is the callback for `NativeMenuEntry::owned_movie_patch`, supplied before installing the existing byte-verified owned native file loader hook. It validates exact paths, complete original/patched SHA256 and original edit bytes before touching the borrowed loader buffer; no pointer is retained. Unknown paths and modified assets fail closed. Already patched buffers are accepted idempotently only under their full patched hash. Counters `native_art_movie_patched` and `native_art_movie_rejected` distinguish application from asset mismatch. These edits apply when native movies load: pre-existing instances are not changed retroactively, and patched instances persist until native movie reload/process exit. Shared game resource files and settings are not edited.

Native crosshair regression evidence: `artifacts/hud-re/interaction-property-abi.txt` proves `2A2C0` takes an AS3 object-record address (it reads its table at +18/index at +20); `interaction-binding-lifecycle.txt` function672BF0 binds the record at element+3A8 and x/y member handles at+660/+670. The pinned `aim-reader-terminal/function-140672f70.txt` disassembly at673188/67318F uses `LEA RCX,[RSI+100]` for another bound object before calling the same setter, independently confirming field-address semantics. The prior fixture incorrectly passed/expected the cached field's first word as the receiver and expected a latch clear every active frame. It now checks the proved record-address ABI and the v220 once-on-handback behavior. Failed handback writes retain restoration intent and retry on the next owned native update rather than silently losing the retry.

The physical hold publication gate now matches PhysicalGrab's existing bounded 250ms tracking age. A continuously valid 5FPS stream (200ms publication interval) no longer falls out of usable at100ms. Unusable publication, tracking loss and observed grip release still release immediately on their consuming native callback. CPU replay covers90/30/10/5FPS held frames, grip release and tracking loss; gaps beyond250ms remain rejected.

Actual extracted movies pass full SHA checks, mismatch/unknown-path/size refusal, edit isolation and idempotence. Patched movies parse through the existing ABC parser with unchanged body counts.
