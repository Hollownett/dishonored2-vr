## Scoped blocked-candidate continuation

Original3b8430 breaks its hit loop when3b7b90 returns blocked and its output byte is0. That early termination assumes camera/fraction order; hand-proximity order breaks the assumption because a nearby-hand blocked item may precede a visible front object.

The extra pinned3B7B90 hook has exact seven-argument ABI `(sensor,entity,origin,axis,point,unsigned range,byte* output)->uintptr_t`. Original is called once with every original parameter. Its full return value is returned unchanged. ONLY for main stage0 call return3B8B05, range0, matching current typed sensor, fresh hand and successfully reordered object result buffer, a blocked result with output byte0 can change that byte to1. The candidate still fails native LOS and remains unselected; the next candidate receives its own complete permission and LOS checks. Additional per-action obstruction calls (returns3B8B47/3B8B95), direct calls and character/Lean jobs remain unchanged.

The same byte also carries character blocked-marker semantics, so continuation requires the candidate to be a proven non-character under the exact native stage0 classifier. The helper decodes only a pure eight-byte `LEA RAX,[RIP+disp32]; RET` vtable[0] getter within the pinned module code range, requires its typeInfo in the known native metadata range, and reads typeInfo+60 against native character bounds39CE2C0/39CE2C4. These are the original selector comparisons. Entity vtable/getter are revalidated; no extra engine call is issued. Unknown getter form/metadata and character candidates leave return/output unchanged. Thus unknown classes may still early-terminate a reordered scan; this is a fail-closed limitation rather than forced acceptance.
