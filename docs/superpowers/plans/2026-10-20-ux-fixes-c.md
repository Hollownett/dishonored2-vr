# UX Fixes C: Default-On Features, Hold-Y Menu, VR From the First Frame, Stealth Kills From Behind Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After the user's v601 headset test (2026-10-20): (1) the launcher ships with every approved feature on, each one switchable in a launcher page; (2) holding Y in gameplay opens the VR settings menu without losing Y's short-press meaning; (3) a game started from the launcher is in VR as soon as that is safe, with no long flat phase; (4) the user stops missing stealth kills on a guard hit from behind, first by collecting the evidence that names the cause, then by the near-pass assist and whichever cause-specific fix the evidence selects.

**Architecture:** One data file (`tools/default_features.json`) lists the default-on features; the C# launcher (`launcher/Features.cs`, pure, no WinForms) and the Linux installer (`linux/d2vr_linux/modhome.py`) both apply it to `build\` in the mod home and persist the user's opt-outs in `build\launcher-features.json`. A pure `YHold` tracker in `src/y_hold.hpp` turns a held left-Y into a one-shot "open settings" request in `GameXr`, while a short Y still reaches the game. A pure `StartGate` in `linux/proxy/proxy_core.hpp` replaces the fixed 45 s settle with "game window found and first real swapchain present seen and a short settle"; the Windows launcher gets the same behaviour either by polling (quick win) or by loading the proxy at process start, chosen by an investigation task. The stealth work is a read-only evidence task, a pure near-pass assist in `src/sword_contact_policy.hpp`, a Linux simulated-VR scenario, and a decision-table-driven fix task.

**Tech Stack:** C++17 headers (MSVC `cl /W4 /WX`, clang-cl + Wine on Linux with the `-Wshadow` family as errors), C# net8.0 (launcher, WinForms; a separate console test project for the pure parts), Python 3 stdlib (`linux/d2vr_linux`, `unittest`), the Wine-hosted `proxy_check`, `linux/d2vr-linux sim` scripted sessions.

**Spec:** the "Requirements" section of this plan (written from the user's words of 2026-10-20). Facts used: `docs/PLAYING.md` (Experiments, VR settings), `docs/LAUNCHER.md`, `linux/README.md`, `docs/BONELAB-FEEL-SIM-SAVES.md`.

## Requirements

User, 2026-10-20, after the v601 headset test, verbatim: "I still miss stealth kills when I trying to hit guard from behind. When I trying launch a game from VR launcher the game first starts as flat game - correct behavior is that game should start in VR immediately without flat game step. Launcher should contain all features by default. ... in game menu should appear by holding "Y" button."

Numbered requirements the tasks cite:

- **R1 (stealth).** A fast sword stroke at an unaware guard from behind or the side kills him silently (leg, torso or head). Missing it is a bug. The cause is not known yet; the plan collects evidence before choosing a fix, and adds the near-pass assist (RCA) regardless.
- **R2 (VR immediately).** Launching from the VR launcher starts the game in VR without a flat phase the user has to wait through. VR starts as soon as it is safe; a knob restores today's delay if a game start proves unstable.
- **R3 (all features by default).** The launcher's first start leaves the user with every headset-approved feature on and nothing to hand-edit; each feature can be turned off in the launcher and the choice persists. The Linux installer writes the same defaults.
- **R4 (hold Y).** Holding the left-controller Y button in gameplay opens the VR settings menu. A short Y keeps today's meaning (Y on an offered Talk prompt; the wheel's quick action).

## Review Focus

1. **Short-Y regression.** A 100 ms tap on Y while an NPC offers Talk must still talk; a 0.6 s hold must open settings and must not also talk, press the wheel quick action, or reopen on release. Pinned by Task 4 `short_press_never_fires`, `hold_fires_once`, `talk_offer_suppresses_hold` and the existing `controller_input_check`.
2. **A knob the user turned off coming back.** Every launcher start and every Linux `install` re-applies defaults; none may resurrect a feature the user disabled, nor delete a hand-made `no-*` file. Pinned by Task 2 `disabled_feature_stays_off_after_apply`, `handmade_negative_knob_is_adopted`, `apply_is_idempotent`.
3. **Starting VR too early.** A start before the game's D3D device and window exist must not wedge the game or leave a half-started session (`StartProbe` returns 2/3, or retries forever). Pinned by Task 6 `gate_requires_present_and_settle`, `gate_never_opens_before_window`, `timeout_fallback_is_old_delay`, and the Wine `proxy_check` early-start case.
4. **The stealth assist turning into a hit-through.** The near-pass must never fire for an aware or frontal guard, a slow swing, a guard behind a wall, or a blade that is moving away. Pinned by Task 8 `near_pass_rejects_frontal`, `near_pass_rejects_slow`, `near_pass_rejects_moving_away`, and the game-thread checks staying in force.
5. **Diagnosis counters that lie.** Reject counters must add up (every contact lands in exactly one bucket) or the decision table points at the wrong fix. Pinned by Task 1 `report_buckets_sum_to_contacts`.
