# H6: DLSS implementation plan

2026-10-22. Implements the [paired-eye design](../specs/2026-10-22-dlss-design.md); this document itself implements nothing.
This assigned H6 planning subtask is documentation only: do not build, probe, simulate, run the game/GPU/headset, download/copy a provider, contact anyone, or change engine code during planning.
All tasks below are subsequent work. Offline implementation may continue under the existing user request; runtime/headset work requires the user to lift the no-game/no-GPU restriction.
SDK/provider publication and trademark terms remain separate release prerequisites under the [pinned license][license], including SDK linkage even with a user-supplied DLL. No legal approval or provider-shipping authorization is assumed.

## Execution rules

Order: T1–T5 offline → authorized T7 DLAA → T6 Quality → T7 Quality → T8 for both modes. Run code tasks sequentially because their shared `FsrTaa`/`dxgi_probe.cpp` integration must not overlap H5 or other engine edits; reread current source and reconcile the baseline before each task.
Each task may edit only its listed footprint; stop and revise scope if another file is necessary. Do not revert concurrent changes or assume this plan's author owns HEAD.
Preserve locomotion/turning, existing mode meanings 0..6, existing FSR/SMAA behavior, sharpening, LOD bias and global knobs.
Initial provider lane: already user-supplied signed `nvngx_dlss.dll`, explicit path, no bundling/download/copy automation. SDK sources/libraries must be separately pinned and terms/provenance recorded.
No time-to-working-picture commitment: input ownership and headset quality are still unproven.

## T1 — SDK-independent receipt and executor contract

Allowed: NEW `src/temporal_eye_job.hpp`, NEW `tests/temporal_eye_job_check.cpp`.
Define frozen pre-split render-input receipts from the design: exact eye/pair/frame, resource/depth/MV provenance, dimensions/rects/formats, device/backend/feature/reset/jitter generations and retained owner leases. Keep staged recording envelopes and execution inputs separate.
Define ordered prefix → depth snapshot → evaluate-or-fallback → remainder behavior with no NGX or D3D device dependency. Reserve context identity, acquire immutable prefix identities only after successful splits, and seal the envelope's list identities/chain order only when `finished` attaches the retained remainder; accept the caller's execution restore flag only at execution.
Use instrumented fake references/executor to assert these phase boundaries, exact operation order and destruction after lease retirement, including chained eyes/interleaved contexts. Assert valid pre-split receipts need no future list/restore values, sealed identities cannot change, and both execution restore values pass through independently of the split's `FinishCommandList(TRUE)` recording-state flag.
Test slot exhaustion/pre-split rejection, list-address reuse, missing/stale depth or MV stamps, wrong eye/frame/shape/device/backend/reset generations and disabled backend; stale temporal jobs must still execute every native list exactly once.
Gate: CPU tests pass without GPU/provider calls; tests deliberately exercise observable scheduling/fallback invariants, not source-text matching.

## T2 — Typed NGX owner and compile-only integration

Allowed: NEW `src/dlss_eye_upscaler.hpp`, NEW `tests/dlss_lifecycle_check.cpp`, NEW `tests/dlss_sdk_compile_check.cpp`, NEW `tools/build-dlss-compile.cmd`; `tools/build-msvc.cmd`; NEW files under `third_party/dlss/include/` plus `third_party/dlss/source.json`, `third_party/dlss/LICENSE.txt`, `third_party/dlss/lib/nvsdk_ngx_d.lib`; `THIRD_PARTY_NOTICES.md`.
Acquire SDK material only under the authorized SDK terms; record commit `9981c6350dc58c0ce21f024fd65e31e851c31689`, hashes, exact source paths and transitive header closure. No provider binaries belong in this footprint.
Implement one serialized device owner with SDK-typed injectable call table, SDK-owned parameters, two independent eye feature/parameter sets and explicit immediate-context create/evaluate/release ownership. [SDK][sdk], [helpers][helpers].
Implement bounded lifecycle, partial-pair rollback, official SDK/Core signature/path validation, capability/driver/device/dimension failures, retirement and safe shutdown. Windows/Proton signature/discovery behavior remains a runtime gate; do not assume Wine Authenticode support. The SDK loader finds Core; feature paths find the provider. No provider-export casts or standalone D3D11 header shim.
Use `/MD` and SDK `nvsdk_ngx_d.lib`; add a compile/link-only command that builds the typed ABI check and production DLL without executing either or any existing GPU test. Keep normal build behavior compatible. [Guide §5.1.1][guide].
CPU lifecycle tests inject init/capability/create/evaluate failures at each eye, verify release/parameter/shutdown order, serialized calls, retry policy and failure reasons; no real NGX/device initialization.
Gate: CPU tests plus Windows x64 MSVC `/W4 /WX` compile/link pass with pinned SDK and production `/MD`; archive commands/toolchain/library hashes. If native toolchain is unavailable, record a blocked compile gate, not a substitute proof from mocks.

## T3 — Integrate retained jobs at the existing immediate seam

Allowed: `src/fsr_taa.hpp`, `src/temporal_eye_job.hpp`, `src/dlss_eye_upscaler.hpp`, `src/dxgi_probe.cpp`, `tests/temporal_eye_job_check.cpp`, `tests/dlss_lifecycle_check.cpp`.
Wire pre-split render-input freezing into `replace`/`post_tonemap_end`, successful split prefix retention into the staged recording envelope, exact remainder ownership/envelope sealing into `finished`, and caller-supplied execution restore behavior into `execute`/`dispatch`; preserve `TaaDispatchHook::execute_handler` and its timing/world-UI wrapper.
Add explicit producing eye/frame/sequence stamps for upscale MV and generation-bound depth resource/view ownership. Do not certify heuristic depth selection as eye correctness; expose its boundary/identity for later evidence.
Create features at a serialized immediate-context lifecycle point, outside deferred recording; perform eye-private depth/color snapshots after each prefix, evaluate to an intermediate, commit to native output only on success. Validate copy-compatible descriptors for `CopyResource`; it cannot crop/convert. Use an explicit conversion/crop pass for differing formats/rects (e.g. RGBA16F → R11G11B10), with failure preserving fallback.
Reject stale DLSS work safely; preserve lists and ready FSR fallback with forced reset on backend transitions, then native color-copy/upscale bilinear fallback. Pre-split refusal alone preserves native TAA.
Keep coherent pair-generation publication; report mixed results as fallback, invalidate DLSS pair success and reset both histories. Keep SMAA/eye postprocessing.
Gate: extend fake-executor tests to assert render-input freeze → split/prefix acquisition → `finished`/remainder sealing → execution flag arrival, immutable identities at their respective phases, and both execution restore values independent of `FinishCommandList(TRUE)`. Cover failed first/second eye, fallback failures, copy-descriptor mismatch/conversion rejection, queued resize/reset, device loss and retirement; rerun native compile/link only. No GPU or game validation yet.

## T4 — DLSS-only 32-phase projection jitter

Allowed: NEW `src/dlss_jitter.hpp`, NEW `tests/dlss_jitter_check.cpp`; `src/dxgi_probe.cpp`, `src/fsr_taa.hpp`, `src/temporal_eye_job.hpp`, `tests/temporal_eye_job_check.cpp`.
Replace the current engine eight-phase sequence only for a pending/active paired DLSS generation: deterministic 32-phase subpixel samples, current/previous per eye, same sample for both eyes, one advance per rendered pair. [Guide §3.7][guide].
Update actual rendered projection and engine current/previous constants coherently with NGX receipt jitter; validate the existing native ABI before takeover and refuse unsupported paths.
Reset sample/history on transitions, skipped/discontinuous pairs and camera cuts; restore existing jitter when leaving DLSS. Do not claim the current live sequence is FSR-driven.
Keep alternate-eye DLSS unavailable; leave the separate `nativeGameTAA` candidate and user-accepted locomotion/turning untouched.
Gate: CPU sequence coverage/bounds/determinism, pair advancement, previous/current correspondence, reset/switch/failed-eye/alternate rejection tests; native compile/link. These tests cannot prove actual projected jitter or MV signs.

## T5 — Diagnostic paired DLAA and honest backend reporting

Allowed: `src/dlss_eye_upscaler.hpp`, `src/fsr_taa.hpp`, `src/dxgi_probe.cpp`, `src/temporal_eye_job.hpp`, `tests/dlss_lifecycle_check.cpp`, `tests/temporal_eye_job_check.cpp`.
Add a fixed-native-dimension diagnostic DLAA opt-in through the existing configuration mechanism; require both features ready before allowing a DLSS takeover. Keep it out of normal selectable AA modes for this stage.
Represent native-color and post-tonemap color/exposure contracts separately; reject unknown formats/subrects. Carry explicit MV scale/jittered/reversed-depth flags; do not tune signs globally or repurpose the reactive mask blindly. [Guide §§3.1, 3.6–3.9][guide].
Report requested mode, per-eye/pair actual backend, reason, dimensions, stamps and generations; add accurately named NGX timing/failure fields rather than reusing FSR labels.
Gate: injected missing/invalid provider, missing Core, unsupported adapter/driver, partial create and evaluate failure remain recoverable; CPU receipt/lifecycle tests and native compile/link pass. Diagnostic availability is not visual acceptance.

## T6 — Quality dimensions and compatible AA preferences

Allowed: `src/dlss_eye_upscaler.hpp`, `src/fsr_taa.hpp`, `src/dxgi_probe.cpp`, `src/vr_preferences.hpp`, `src/vr_settings.hpp`, `src/vr_settings_native.hpp`, `src/settings_panel_image.hpp`; NEW `tests/dlss_preferences_check.cpp`; `tests/vr_settings_check.cpp`, `tests/vr_settings_native_check.cpp`, `tests/render_scale_transaction_check.cpp`, `tests/dlss_lifecycle_check.cpp`.
Begin only after T7's paired DLAA input/recovery gate passes. Append 7 = DLAA and 8 = DLSS Quality; preserve 0..6 and migrate saved preference versions without reinterpretation. Defer other DLSS modes.
Query `NGX_DLSS_GET_OPTIMAL_SETTINGS` for Quality; validate recommended/min/max dimensions and active/full rects, apply paired render-scale transaction, then recreate both features for the committed generation. No fixed quality percentage. [Helpers][helpers].
Limit DLSS to fixed supported dimensions initially; suspend dynamic governor stepping for its request only. Reject incompatible dimensions without altering existing modes/global knobs.
Only enable selectable labels after capability and both feature creations succeed for that mode/device/dimensions; pending requests and fallback must expose requested versus actual mode and the reason, including persisted requests on unsupported machines.
Gate: meaningful preference migration/round-trip/out-of-range tests, capability-aware cycling, partial-create unavailability, resize invalidation, optimal-settings boundary failures and transactional rollback; native compile/link. Repeat T7/T8 for Quality before release.

## T7 — Authorized Windows RTX runtime input and recovery gate

Prerequisite: user explicitly lifts no-game/no-GPU restriction; T1–T5 offline gates pass. Allowed code: none; evidence only in ignored `.superpowers/sdd/2026-10-22-windows-feedback-h/`.
Use only the user-supplied signed provider. Record Core/provider discovery, adapter/driver, capability/create results, runtime versions, per-eye features and immediate contexts; a DLL load is not successful presentation.
Prove shared-depth producer → prefix → eye snapshot ordering, eye/frame MV contents, active/full rectangles, actual 32-phase projection jitter and previous-frame convention, MV signs/scales, reversed depth, color encoding/exposure and accepted formats using bounded diagnostics/debug-layer evidence.
Exercise both eyes/chained lists, both restore flags, missing provider at startup, evaluate failure per eye, fallback, mode switch, load/teleport/cut, resize, device loss/recovery and owner retirement; require clean state and coherent stereo publication.
If evidence fails, stop DLSS availability and scope a corrective task; CPU mocks cannot close this gate. Native DLAA passes before T6; Quality repeats this gate after T6. T7 establishes input/recovery evidence, not headset quality; T8 remains mandatory for both modes.

## T8 — Authorized headset and Proton acceptance

Prerequisite: T7 passes and runtime restriction is lifted. Allowed code: none; evidence only in ignored `.superpowers/sdd/2026-10-22-windows-feedback-h/`.
When VR is requested, launch the reviewed candidate directly with `-SkipPreflightWait`, preserving OpenXR initialization/recovery; no separate headset-detection probes.
Compare paired DLAA/Quality against accepted modes for static shimmer, motion disocclusion/ghosting, tracked avatar/weapons, HUD/text, stereo stability, comfort and measured CPU/GPU cost. Record user's headset feedback; no automated complete-gameplay or visual-quality claim.
Separately test Linux RTX 3070 under actual Proton/DXVK/DXVK-NVAPI/proprietary-driver versions on the NVIDIA adapter. [DXVK-NVAPI][nvapi] forwards D3D11 DLSS; Proton 9+ normally enables it, with exceptions. Treat legacy `PROTON_ENABLE_NVAPI=1` as configuration history, never success evidence.
Prove Core/provider capability, per-eye create/evaluate and failure fallback under Proton; keep it explicitly unverified until then. Do not change global driver/offload/LOD/sharpening settings as part of this task.
Release gate: both staged modes meet runtime/headset acceptance, fallbacks regress cleanly, SDK publication/notice/trademark obligations are resolved, and release artifacts contain no provider. Any future provider distribution needs a separately reviewed scope.
